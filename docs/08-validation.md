## Отборочный проект

Для отборочного задания я делал [VAVASTO/AIMedicine](https://github.com/VAVASTO/AIMedicine). В этой работе проверил коммит `e2f4877`: запустил только `tests/test_llm.py`, без правки исходников и без сети. Файл содержит 34 проверки, включая кеш, бюджет запросов, квоты, задержки повторов, JSON Schema, неверные ответы и отсутствие утечки ключа.

Полный набор из 262 тестов и прежние live-результаты описаны в README старого проекта. Полный набор я повторно не запускал, сохранённые ответы модели не засчитывал как новые результаты.

Чтобы воспроизвести выбранные проверки, клонируйте отборочный репозиторий, перейдите на коммит `e2f4877`, установите его зависимости и выполните `python -m pytest tests/test_llm.py -q`. Для повторного запуска я использовал Python 3.12.14 и зависимости из `requirements.lock.txt` нового проекта.

## Новое сравнение GLM и Mistral

Подготовил ещё 12 коротких вымышленных историй с отдельными семьями. До запросов зафиксировал тексты, ожидания, промпт, схему и контрольные суммы. Эти случаи не являются вариантами прежней research-03, но написаны для конкретных инженерных проверок и не имеют независимой врачебной разметки.

Сравнил GLM со всей картой, GLM после отбора доступных документов и Mistral с тем же отфильтрованным входом. Зафиксировал `fta/zai/glm-5.3`, `ministral-8b-2512`, температуру 0, 1024 токена ответа и одну попытку. Ожидания и названия ситуаций в запросы не входили. Обе модели видели одинаковый текст схемы; Mistral дополнительно использовала встроенный контроль JSON Schema. Сравнение относится к настроенным способам вызова. Порядок условий чередовал; каждый вариант выполнил один раз.

<div data-table="comparison-results"></div>

Все 36 запросов завершились и прошли схему. У Mistral в истории 04 пропущена обязательная ссылка на направление. В истории 05 запись поступления названа выпиской, а код из метаданных карты использован вместо недоступного кода выписки: получен confirmed вместо insufficient_evidence. В истории 09 оценена полнота протокола вместо его доступности по C02: получен insufficient_evidence вместо confirmed.

Прочитал все 36 объяснений с помощью ИИ-ассистента. Названия моделей при чтении были скрыты, но сводные результаты уже были известны; это проверка разработчика, не независимая врачебная оценка. Содержимого будущих документов не обнаружил. Отметил три неточные формулировки: у Mistral отсутствие описания обсуждения отказа может читаться как отсутствие самого обсуждения, признак актуальности назван датой; у GLM назначение названо приказом. Дословная цитата сама по себе не гарантирует обоснованность: в истории 05 Mistral цитирует существующую фразу без кода, которая не подтверждает её вывод. Исходные ответы не редактировал.

Для следующей инженерной проверки предварительно выбрал GLM с фильтром времени по приоритету ошибок и оснований: 12/12 верных статусов против 10/12 у Mistral. Mistral была быстрее. Различия малого авторского набора не доказывают общего превосходства модели. Фильтр не улучшил наблюдаемую точность GLM: оба условия дали 12/12. Он детерминированно исключает недоступный текст до запроса. После первой пробы изменились и промпт, и случаи, поэтому исчезновение прежней ошибки нельзя приписать одному фильтру.

Использовал ровно 24 новых запроса GLM и 12 Mistral, без повторов и смены маршрута. До запуска FreeTheAI показывал 16/50 использованных запросов, после 40/50; осталось 10. Mistral Free и выключенный API pay-as-you-go проверил перед запуском. Платные настройки не менял. Локальный журнал резервирует попытку до обращения к API; каталог эксперимента не допускает случайного повторного запуска.
