# План оценки качества

Сейчас проверены клиент на имитированных HTTP-ответах, режим без сети, формат синтетических примеров и сборка интерфейса. Подключение к Mistral подтверждено одним реальным техническим запросом. Клинические метрики нового проекта ещё не измерены.

## Эксперименты следующего этапа

| Уровень | Метрика | Как измерять |
|---|---|---|
| Поиск | Recall@5 по размеченным основаниям | Доля всех размеченных релевантных фрагментов, попавших в первые пять результатов, отдельно для каждого запроса |
| Ссылки | Доля существующих ссылок и совпавших цитат | Проверка идентификаторов, версии документа и текста; цель для принятых замечаний 100% |
| Замечания | Precision, recall, F1 | Сопоставление с размеченными врачом замечаниями по случаю и коду |
| Ложные тревоги | Доля контрольных карт с неверным замечанием | Оценивать отдельно на чистых примерах; проверки внесённых дефектов недостаточно |
| Неопределённость | Доля правильных отказов | Пустой поиск, неизвестная тяжесть, выход за границы, конфликт фактов |
| Устойчивость | Ошибки формата и повторяемость | Несколько запусков на одинаковых данных; неверный JSON, обрезанный ответ, недоступный API |
| Скорость и стоимость | p50/p95 задержки, токены на случай | Фиксировать модель, дату, настройки и число попыток, включая повторы |
| Работа врача | Время проверки и полезность замечаний | Один протокол, сопоставимые случаи, чередование ручной и автоматизированной проверки |

Порогов клинического качества пока нет: сначала нужны экспертная разметка и базовый замер. Целевые 90% из общей идеи проекта не выдаются за результат.

## Сравниваемые варианты

Базовая проверка обязательных полей без LLM, Mistral с RAG и, после получения доступа, Gemini с тем же корпусом и схемой ответа. Сравнение проводится на одинаковых версиях случаев. Полезность модели оценивается сверх простой проверки полей.

Планируем начать с 30 независимых базовых историй после согласования с врачом: 20 для разработки, 10 для закрытой проверки. Все мутации одной истории остаются в той же части. Это план, текущий набор содержит только одну семью из восьми примеров. Для уверенных выводов о клиническом качестве такого пилота недостаточно; в отчёте нужно показывать абсолютные количества и интервалы неопределённости.

Врач размечает замечания и точные основания, второй проверяющий рассматривает спорные случаи. Сначала измеряем согласие экспертов, затем качество модели. Разногласие нельзя скрывать заменой эталона под полученный ответ.

## Что сохранять

Идентификаторы и версии случаев, хеш корпуса, выбранные фрагменты поиска, версию промпта, модель из ответа сервера, настройки, расход токенов, задержку и исход проверки. Для первого технического вызова используется фиксированный текст без пациентов. В публичные отчёты попадают только синтетические данные и агрегированные результаты.
