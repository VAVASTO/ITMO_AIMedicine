# Существующие решения и доказательства их эффективности

Я сравнил 12 подходов и продуктов: ручную экспертизу, формальные проверки в МИС, прямые российские аналоги и смежные зарубежные системы. Искал решения по двум рабочим процессам, затем проверял сайт разработчика, руководство или первичное исследование. Журнал запросов и решений о включении находится в `research/search-log.csv`. Обзор целевой, он не претендует на исчерпывающий каталог рынка.

Схемы показывают подтверждённый пользовательский процесс. Если устройство модели или поиска не раскрыто, я не восстанавливаю его по рекламе. Эффективность разделяю на измеренную в исследовании, заявленную поставщиком и неизвестную для выбранной задачи. Во всех случаях продукты исследованы по открытым материалам; самостоятельного испытания на одинаковых картах не было.

## Ручная экспертиза

<div data-flow='Ручная экспертиза'></div>

Человек проверяет документы, применимость требований и исключения, формулирует заключение.

**Доказательства.** Регламент описывает процедуру и роли. Время и согласие экспертов в выбранной организации пока не измерены.

**Вывод для проекта.** Гибко учитывает контекст, но результат зависит от полноты документов и воспроизводимости рассуждения. Это обязательная точка сравнения; эксперт участвует и в проверке ИИ. [N231](https://ak.reso-med.com/upload/iblock/470/d42wmdfv8pm6olg72ucsp1v0rhls0vy9/Prikaz-Minzdrava-RF-ot-19.03.2021-N-231N-Ob-utverzhdenii-Poryadka-provedeniya-kontrolya-obemov_-srokov-_red-04.09.24_.pdf)

## 1С:Медицина. Поликлиника

<div data-flow='1С:Медицина. Поликлиника'></div>

Формализованные критерии и отметки выполнения помогают вести клинико-экспертную работу.

**Доказательства.** Публичная документация описывает функции, но не даёт сравнительной точности. Страница ссылается на приказ 2017 года; состояние установленного продукта по ней неизвестно.

**Вывод для проекта.** Полезный базовый подход для обязательных полей и кодов. Рассмотренный модуль амбулаторный; свободный текст и исключения требуют отдельной проверки. [ONEC](https://solutions.1c.ru/catalog/clinic/expert)

## ОМС-Эксперт / СДК-Сатурн

<div data-flow='ОМС-Эксперт / СДК-Сатурн'></div>

Прямой аналог: МКБ-10, КСГ, оформление карты, клинические критерии и требования ОМС. В руководстве есть статусы чтения, ошибки и таблица с требованием, обоснованием и фрагментом карты.

**Доказательства.** Поставщик заявляет пять минут на карту. Это не независимый результат и не оценка полноты выявления дефектов. Руководство описывает локальную установку в контейнере; алгоритм поиска и модель не раскрыты.

**Вывод для проекта.** Нельзя заявлять новизну самой автоматической проверки карты. Для сравнения нужны одинаковые случаи и доступ к продукту; сейчас его нет. [SBER](https://sbermed.ai/our-algorithms/oms-expert) [SATURN](https://sbermed.ai/uploads/Rukovodstvo_po_ekspluataczii_Saturn_68565ba3d5.pdf)

## Webiomed: контроль выполнения КР

<div data-flow='Webiomed: контроль выполнения КР'></div>

Сервис 2026 года использует LLM, выделяет выполненные, недостающие и избыточные назначения; предоставляет API и навигацию по основаниям.

**Доказательства.** Более 500 рекомендаций указаны производителем. В публикации нет независимой оценки ошибок и эффекта на оплату.

**Вывод для проекта.** Близкий конкурент в экспертной ветви. Важны различение назначений и выполнения, интеграция с МИС и видимость источника. Преимущество предложенного подхода ещё предстоит доказать. [WEBIOMED](https://webiomed.ru/novosti/kontrol-klinicheskikh-rekomendatsii/)

## Панацея

<div data-flow='Панацея'></div>

Объединяет поддержку приёма, справочник и проверку карт; модуль ДМС учитывает покрытие назначений.

**Доказательства.** На сайте описаны функции и масштабы использования. Публичной сопоставимой оценки точности в просмотренных материалах нет.

**Вывод для проекта.** Рассматриваю как конкурента по помощи врачу и внутреннему контролю. Правила ДМС отличаются от ОМС; поддержку всех задач страхового эксперта по сайту установить нельзя. [PANACEA](https://panaceadoc.ru/)

## Defect AI

<div data-flow='Defect AI'></div>

Проверяет документацию и услуги, готовит разбор дефектов и основания для возражений; есть стационарные сценарии.

**Доказательства.** Заявленные проценты снижения дефектов не сопровождаются в источнике описанием сопоставимого эксперимента. Юрисдикция: Казахстан.

**Вывод для проекта.** Полезен устройством полного экспертного процесса. Российские нормы, тарифы и формы придётся проверять отдельно; переносить результат автоматически нельзя. [DEFECT](https://defect.kz/)

<div data-flow='UpToDate Expert AI'></div>

**Вывод для проекта.** Показывает ценность подготовленного корпуса. Для процесса проекта нужен ещё слой фактов карты и проверка применимости к случаю. [UPTODATE](https://www.wolterskluwer.com/en-au/news/uptodate-expert-ai-genai-clinical-decision-support)

**Вывод для проекта.** Смежный инструмент врача. Для сравнения нужен отдельный набор медицинских вопросов; смешивать его с оценкой дефектов документации нельзя. [OE](https://portal.openevidence.com/)

## Abridge

<div data-flow='Abridge'></div>

Подготовка медицинских записей, сценарии врача и revenue cycle.

**Доказательства.** Публичное описание продукта. Поддержку американского процесса оплаты нельзя считать подтверждением пригодности для ОМС.

**Вывод для проекта.** Помогает на этапе создания исходной записи. Ошибки черновика могут перейти в аудит, поэтому связь с первичным фактом должна сохраняться. [ABRIDGE](https://www.abridge.com/)

## Nabla

<div data-flow='Nabla'></div>

Автоматическая подготовка записей после приёма; один из двух продуктов в опубликованном РКИ.

**Доказательства.** Время написания записи уменьшилось на 9,5% относительно контроля. Условия и доверительный интервал приведены в разделе оценки.

**Вывод для проекта.** Есть экспериментальные данные для конкретного амбулаторного процесса. Они не измеряют точность аудита в проекте и не заменяют испытание на русском языке. [RCT](https://doi.org/10.1056/AIoa2501000)

## Microsoft DAX Copilot

<div data-flow='Microsoft DAX Copilot'></div>

Второй продукт в том же РКИ, что позволяет сравнить результаты в одном дизайне.

**Доказательства.** Статистически значимого сокращения времени написания записи относительно контроля по первичному исходу не показано.

**Вывод для проекта.** Нельзя считать любой ИИ автоматически экономящим время. Нужен эксперимент с полным временем работы, включая исправление ответа. [RCT](https://doi.org/10.1056/AIoa2501000)

## Что следует из сравнения

Для проверки российского стационарного случая ближайшими аналогами оказались ОМС-Эксперт и сервис контроля КР Webiomed. Панацея закрывает близкие задачи приёма и внутренней проверки. В первоначальном обзоре я пропустил эти прямые сценарии и слишком много внимания уделил поисковым помощникам и составлению записей.

Мой проект не может претендовать на новизну за счёт сочетания LLM и медицинских рекомендаций. Проверяемая исследовательская гипотеза уже: явный учёт времени доступности факта, применимости требования и двух оснований замечания уменьшит число необоснованных замечаний по сравнению с проверкой всего текста одним запросом. Гипотеза пока не проверена; сходные функции у конкурентов могут существовать и не быть раскрыты в открытых материалах.

Формальные ошибки удобнее искать правилами. Поиск по знаниям помогает подготовить основание. Модель полезна для извлечения и объяснения неоднозначного текста, но требует проверки. Человек остаётся участником решения там, где важны исключения и клиническая обоснованность. Поэтому архитектура сочетает эти подходы, а эксперимент сравнивает их вклад отдельно.
