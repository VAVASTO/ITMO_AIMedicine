# Закрытая демонстрация

Я подготовил приложение для размещения за HTTPS и входом по паролю. Внешнего адреса пока нет. Docker в рабочем окружении не установлен, поэтому сборка контейнера здесь не проверена. Python-приложение, интерфейс и защита проверяются отдельно локально.

## Состав

В образ входят код, вымышленные случаи, четыре короткие карточки и сохранённые ответы моделей. Исходные ключи, локальные настройки, полный PDF и текст источника исключены из контекста сборки. Новые запросы к Router во внешней демонстрации отключены по умолчанию. Сценарий действий врача и сохранённые сравнения работают без ключа.

До размещения нужно согласовать содержание, объём и формат раскрытия результатов по п. 4.1 NDA, а также состав авторов и аффилиацию по п. 4.2. Я не назначал соавторов и не отправлял материалы от имени компании. Пакет для проверки находится в `docs/15-clinical-review.md`.

## Запуск на выбранном сервере

Нужны Docker, HTTPS-прокси и закрытый файл настроек на сервере. В файл настроек владелец сервера задаёт `APP_DEMO_PASSWORD`. Пароль нельзя добавлять в репозиторий или в публичную команду запуска. Логин для входа: `demo`.

```bash
docker build -t itmo-aimedicine .
docker run --rm --name itmo-aimedicine \
  --env-file /absolute/private/demo.env \
  -p 127.0.0.1:8001:8001 \
  --read-only --tmpfs /tmp \
  itmo-aimedicine
```

Прокси должен передавать запросы на `127.0.0.1:8001` и требовать HTTPS. Пароль передаётся через HTTP Basic только поверх HTTPS. Без `APP_DEMO_PASSWORD` приложение с `PUBLIC_DEMO=1` отвечает 503. Без правильного пароля все страницы и API отвечают 401. Режим `/api/smoke` во внешней демонстрации выключен.

Для полнотекстового поиска нужен локально построенный `clinical-search-v2.db`. Его можно подключить отдельным read-only mount после согласования содержимого источника. Без индекса поиск сообщает, что он не настроен; остальные функции доступны.

## Если понадобятся новые ответы моделей

Это отдельная настройка сервера: `DEMO_ALLOW_LIVE=1`, серверный ключ Router и `DEMO_DAILY_JOB_LIMIT`. По умолчанию лимит приложения составляет 8 заданий в сутки UTC, то есть 4 нажатия по два задания. Он действует сверх квоты Router и не считает исследовательские запуски из командной строки. Неудачный или прерванный запуск также резервирует два задания, чтобы повторные клики не обходили лимит.

Каталог `reports/live/` должен быть отдельным постоянным writable volume. Без него read-only образ намеренно не поддерживает живые вызовы. Используется один процесс приложения; лимит не предназначен для нескольких реплик. Журналы нельзя удалять для сброса лимита. Перед живым запуском нужны остатки квоты в Router и проверка сервера с настоящими настройками. Пароль, TLS, журналирование и срок доступности демонстрации определяются для конкретного хостинга.

## Что проверено и что осталось

Локальные тесты проверяют отказ без пароля, неверный пароль, запрет чужого Origin, отключение живых вызовов и остановку по дневному лимиту до вызова провайдера. Сборка Vue проверена. Контейнер, HTTPS, DNS и доступ извне ещё не проверены: сервер и домен не выбраны.
