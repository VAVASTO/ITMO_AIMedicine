# Подключение Mistral и GLM, доступ к Google

18 октября 2026 года я подключил Mistral и проверил соединение одним техническим запросом без медицинских данных. За основу взял клиент из [отборочного проекта AIMedicine](https://github.com/VAVASTO/AIMedicine/tree/e2f4877).

## Что произошло с Google

После входа Google AI Studio перенаправлял на [страницу доступных регионов](https://aistudio.google.com/docs/available-regions); ранее появлялась ошибка получения списка моделей. Создать ключ не удалось.

18 октября 2026 года я повторно попробовал создать ключ с телефона через VPN с выбранной локацией США. Кнопка создания ключа была недоступна либо интерфейс указывал на отсутствие прав. Точный текст ошибки я не сохранил, причину ограничения пока не установил. Ключ получить не удалось.

Gemini и Gemma пока не вызывались, поэтому этот пункт задания остаётся незавершённым. Для продолжения разработки я подключил Mistral; его техническая проверка прошла успешно. После решения проблемы доступа планирую вернуться к Google AI Studio и проверить модели на том же наборе примеров.

## Что перенесено из примера

В `aimedicine/llm.py` отборочного проекта используется официальный HTTPS endpoint, переменные окружения, JSON Schema и проверка ответа через Pydantic. Также ограничены попытки, обработаны квоты и обрезанные ответы. Эти решения я адаптировал в `itmo_aimedicine/llm.py`.

В новом клиенте нет дискового кеша: для технической проверки он не нужен и мог бы скрыть отсутствие свежего ответа API. После неоднозначной сетевой ошибки автоматического повтора нет, чтобы не дублировать потенциально оплаченный запрос. Повтор предусмотрен только для 429, 502, 503 и 504, максимум три попытки на один вызов. Между попытками есть ограниченная пауза.

| Назначение | Сейчас | Дальше |
|---|---|---|
| Проверка соединения | `ministral-8b-2512`, успешный технический JSON | Доступ подтверждён; клиническое качество ещё не проверено |
| Подготовка объяснений в следующем эксперименте | Предварительно `fta/zai/glm-5.3` | 12/12 статусов против 10/12 у Mistral на тех же отфильтрованных входах; клиническое качество неизвестно |
| Проверка результата | Формальные правила и проверка человеком | Отдельную LLM-проверку оценить как дополнительный вариант |
| Сравнение провайдеров | GLM и Mistral проверены на 12 историях; Gemini/Gemma отложены | Продолжить на новых случаях и после доступа добавить Google |

В ответе API подтверждена модель `ministral-8b-2512`: 49 входных и 24 выходных токена, всего 73; одна попытка, 763 мс. Формат JSON прошёл проверку схемы. Это проверка соединения, а не оценка качества медицинских ответов.

## Выбор модели и распределение работы

Для сравнения зафиксировал `ministral-8b-2512` без плавающего обозначения `latest`: эту версию уже использовал в техническом запросе. Официальная карточка подтверждает поддержку Structured Outputs и Chat Completions. Вторым участником стала `fta/zai/glm-5.3`, доступная через бесплатный маршрут FreeTheAI. Такое ограничение позволяет провести эксперимент с готовыми адаптерами; оно не означает, что выбраны лучшие из всех доступных моделей. Медицинское качество пока не проверено. [MISTRAL8B](https://docs.mistral.ai/models/ministral-3-8b-25-12)

| Шаг | Исполнитель | Почему и что проверять |
|---|---|---|
| Приём JSON, даты, доступность, точное сравнение кодов | Python, формальные правила | Результат воспроизводим; модель не нужна для сравнения двух известных значений |
| Поиск требования | Точное извлечение по известным ключам; для свободного вопроса BM25 с фильтрами | Пилот на 12 запросах поддерживает такой выбор только при вручную заданных ключах; общий корпус ещё не проверен |
| Извлечение сведений из свободного текста и проект объяснения | Предварительно `fta/zai/glm-5.3`, один и тот же ID при сравнении модулей | JSON со статусом, фрагментами и ссылками; неоднозначность сохраняется, новые факты добавлять нельзя |
| Проверка формата, ID, точности цитаты и времени | Python после ответа модели | Некорректный ответ отклоняется; существующая цитата сама по себе не доказывает смысловую верность |
| Применимость клинического требования, исключение и окончательное замечание | Врач или эксперт | Эти решения пока не подтверждены модельными экспериментами; автоматического клинического допуска нет |

После первой пробы GLM провёл 36 запросов на 12 новых историях. GLM со всей картой и после фильтра времени дала по 12/12 ожидаемых статусов; Mistral с тем же отфильтрованным входом дала 10/12. Все автоматические проверки прошли соответственно 12/12, 12/12 и 9/12 ответов. Медианы задержки составили 9,69, 9,67 и 2,56 секунды. По заранее выбранному приоритету ошибок и оснований предварительно выбираю GLM для следующего эксперимента; настройка приложения по умолчанию пока остаётся Mistral. Это малый авторский набор, без оценки клинического качества.

Для эксперимента выбрал одну попытку, последовательные запросы, `temperature=0` и до 1024 выходных токенов на короткий пример. Эти ограничения реализованы для обеих моделей в сравнительном запуске. Текст схемы одинаковый; Mistral дополнительно использует встроенный контроль JSON Schema, поэтому сравниваются настроенные способы вызова. Обрезанный ответ записывается как ошибка. Нулевую температуру не считаю гарантией идентичности ответов. Техническая проверка Mistral по-прежнему ограничена 128 токенами. При отказе по квоте эксперимент прекращается, перехода на другую модель нет. Приложение пока не проверяет остаток тарифа автоматически.

В Subscription активен Free с включённым объёмом API/Studio на $10 в месяц. Платный перерасход API pay-as-you-go выключен; подписка не менялась. Эти условия зафиксированы при подключении 18 октября и повторно проверены перед сравнением 25 октября 2026 года. Пределы частоты запросов зависят от модели, нагрузочный тест не проводился.

Ключ я создал без срока действия. Он привязан к `Default Workspace`, права на подключения ограничены `Shared only`. Клиент отправляет запросы только в `/chat/completions` и не использует подключения к внешним сервисам. Локальная настройка ограничивает проверку одной попыткой и 128 токенами ответа. Приложение не управляет тарифом, поэтому API pay-as-you-go нужно оставлять выключенным в аккаунте.

## Проба GLM от 25 октября

Подключил `fta/zai/glm-5.3` через FreeTheAI и отправил 15 запросов: один технический и 14 по вымышленным сценариям одной семьи. Все завершились с первой попытки. Модель получила общие правила C01–C06 и ID целевого критерия; ожидаемые статусы и объяснения в запросы не входили. Flash не вызывал.

Во всех 14 ответах целевые статусы совпали с ожиданиями. Медиана задержки составила 8,53 секунды. При чтении ответа на поздний результат нашёл упоминание содержимого будущего документа: правильный статус не гарантировал корректного объяснения. Подробная таблица и ограничение приведены в разделе результатов проверки и в [журнале GLM](../docs/11-glm-trial.md).

Маршрут был отмечен как бесплатный в списке FreeTheAI на дату запуска. Первая проба использовала 15 запросов из сообщённых 49. Перед следующим экспериментом проверил аккаунт: оставалось 34. Дополнительное сравнение использовало ровно 24 запроса GLM; после него аккаунт показал остаток 10. Платные настройки не менял. Клиент делает одну попытку, не следует перенаправлениям и не переключается на другой маршрут при ошибке. Ключ загружается из внешнего файла или окружения, в отчёт и репозиторий не входит.

## Документация API

- [Mistral Chat API](https://docs.mistral.ai/api): формат сообщений и endpoint.
- [Структурированный ответ](https://docs.mistral.ai/studio/conversations/structured-output/custom): JSON Schema.
- [Первый запрос](https://docs.mistral.ai/getting-started/quickstarts/developer/first-api-request): ключ через переменную окружения.
- [FreeTheAI API](https://freetheai.org/docs) и [список моделей](https://freetheai.org/models): подключение GLM и бесплатный маршрут, проверенные 25 октября 2026 года.

Секрет хранится в локальном `.env` или окружении процесса, не возвращается интерфейсу. `mock` и `live` явно разделены. Ошибка реального API заканчивает проверку с ошибкой.

## Порядок перехода на Gemini

1. Подтвердить доступ к AI Studio и доступные модели.
2. Добавить адаптер к контракту `StructuredProvider` и настройки Google.
3. Проверить формат JSON, неполные ответы, ошибки, учёт токенов и ограничения запросов.
4. Запустить техническую проверку, затем сравнение на синтетических примерах.
5. Сменить `LLM_PROVIDER` после проверок. Код клинического процесса менять не потребуется.
