# Данные и источники

## Что подготовлено

Я подготовил восемь вымышленных записей в `data/cases.json`. Их создаёт `scripts/generate_cases.py` без обращения к модели. В `data/expectations.json` отдельно лежат ожидаемые инженерные реакции; эти метки нельзя передавать модели вместе со случаем. Формат входа задан в `schemas/patient.schema.json`.

| Случай | Изменение относительно базового | Ожидаемая реакция будущей функции |
|---|---|---|
| case-01 | Выбранные для теста поля заполнены | Нет замечаний по этим полям; это не утверждение о полной клинической карте |
| case-02 | Нет SpO₂ | Показать отсутствие сведений в записи |
| case-03 | Аллергологический анамнез неизвестен | Запросить уточнение; не считать это отрицанием аллергии |
| case-04 | Исследование назначено, результата нет | Не выдавать назначение за полученный результат |
| case-05 | Результат появился позже момента проверки | Не использовать будущую информацию |
| case-06 | В один момент указаны разные SpO₂ | Показать противоречие, не выбирать число молча |
| case-07 | Возраст 16 лет | Сообщить о выходе за границы первой версии |
| case-08 | Тяжёлое течение | Сообщить о выходе за границы первой версии |

Это одна семья примеров с контролируемыми изменениями, а не восемь независимых клинических наблюдений. Числа и частоты специально выбраны для проверки программных ветвей. Экспертного заключения о реалистичности и полноте разметки пока нет.

## Основа для более реалистичного набора

В редакции рекомендаций 2024 года, раздел 1.3, физическая страница PDF 10, приведена заболеваемость взрослых в РФ за 2022 год: 397,5 на 100 тыс. населения. Там же описаны различия риска по возрасту и сопутствующим заболеваниям. Это исторические сведения из источника, не оценка на 2026 год. Они обосновывают необходимость разных возрастных групп, но не задают пропорции текущего небольшого набора.

При расширении данных сначала составлю таблицу факторов из проверенной редакции рекомендаций: возрастная группа, сопутствующие состояния, тяжесть, полнота документов и время получения результатов. Затем подготовлю независимые базовые истории и внесу по одному контролируемому дефекту. Для распределений нужны явные источники и проверка врача; угадывать доли по тексту рекомендации нельзя.

Разбиение на разработку и контроль выполняется по базовым историям. Варианты одного пациента должны попадать в одну часть, иначе метрики будут завышены. Текущая семья используется только при разработке.
