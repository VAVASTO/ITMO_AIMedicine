# ITMO AIMedicine

Учебный проект помощника врача и проверки медицинской документации. На втором этапе я сосредоточился на терапии взрослых и собрал первый сквозной прототип для внебольничной пневмонии: доступные сведения о пациенте → следующие действия → записанные назначения и динамика → проверка помощи.

Прототип работает с 20 вымышленными историями и четырьмя формализованными правилами. Есть фильтр времени, расчёт интервалов, ссылки на клинический источник, рекомендации и отдельная проверка через Gemini/Gemma. В приложении доступны управляемый сценарий действий врача и поиск по PDF без обращения к моделям. Выбор препарата, дозировка, диагностика и санкции ОМС не реализованы. Источники и правила ещё требуют согласования; клинической валидации нет.

## Запуск локального приложения

Нужны Python 3.11+ и Node.js 22.12+. В корне репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
pip install --no-deps -e .
```

Соберите интерфейс, затем запустите сервер из корня репозитория:

```bash
cd frontend
npm ci --ignore-scripts --no-audit --no-fund
npm run build
cd ..
uvicorn itmo_aimedicine.api:app --host 127.0.0.1 --port 8001
```

Откройте http://127.0.0.1:8001. Режим «Локальные формальные правила» работает без API. Режим «Сохранённые ответы моделей» показывает реальные результаты завершённого эксперимента, если соответствующие журналы есть локально. «Новый запрос через Router» делает два обращения к модели, только после нажатия кнопки. Новая версия передаёт рассчитанные интервалы, а проверяющая роль не видит черновик рекомендаций. Случаи T01–T12 сохранены для исходной версии; V01–V08 позволяют сопоставить две версии. Дневной лимит интерфейса по умолчанию составляет 8 заданий, то есть 4 запуска, в сутки UTC. При изменении момента будущие и поздно внесённые записи исключаются из входа.

Публичная демонстрация ещё не развёрнута. Вход по паролю, отключение живых запросов и дневной лимит добавлены. Подготовлен Dockerfile; Docker в рабочем окружении отсутствует, поэтому контейнер не проверен. До внешнего размещения нужны сервер, HTTPS и согласование раскрытия материалов по NDA. Подробности в [инструкции](docs/14-private-demo.md).

## Gemini и Gemma через ANTEI Router

04.11.2026 обе модели успешно ответили через учебный Router. Это решает подключение для проекта; прежняя проблема прямого выпуска ключа в AI Studio отдельно не устранена.

Создайте локальный `.env.router`, исключённый из Git:

```dotenv
LLM_PROVIDER=router
LLM_MODE=live
ANTEI_ROUTER_KEY_FILE=/absolute/path/to/key.txt
ANTEI_ROUTER_MODEL=gemma-4-31b-it
ANTEI_ROUTER_MAX_TOKENS=4096
ANTEI_ROUTER_JOB_TIMEOUT=600
```

Файл ключа должен содержать только ключ. Можно вместо пути задать `ANTEI_ROUTER_API_KEY` через окружение процесса. Секрет нужен только серверу. Переменные окружения имеют приоритет перед файлом настроек.

Адаптер отправляет задание один раз, сохраняет его идентификатор и проверяет состояние с интервалом 10 секунд. Подмена модели отключена (`fallback=false`). При сетевой ошибке или истечении ожидания автоматической повторной отправки нет. Перед новым запуском нужно проверить состояние прежнего задания в Router. Журналы интерактивных запусков сохраняются локально в `reports/live/`. В приложении допускается удаление внешней Markdown-метки вокруг JSON, с записью `format_cleanup` в журнал. Поля, значения, повторы правил и ссылки по-прежнему проходят проверку. Экспериментальные запуски используют строгий разбор; их исходные ошибки не переписаны.

В эксперименте использую `gemini-3.5-flash-lite` и `gemma-4-31b-it`. Идентификаторы взяты из доступного списка Router. Подписки и платные настройки приложение не меняет. GLM с её отдельным лимитом не вызывается.

## Воспроизводимость

Локальные проверки без моделей:

```bash
python -m pytest -q
python scripts/run_therapy_experiment.py --summarize
python scripts/run_therapy_revision.py --summarize
python scripts/verify_therapy_outputs.py
python scripts/build_week2_report.py
```

Для повторного разбора источника установите исследовательскую зависимость и запустите:

```bash
pip install -e '.[research]'
python scripts/parse_therapy_source.py --download --query пульсоксиметрия
python scripts/check_therapy_search.py
```

Источник закреплён контрольной суммой. Новый PDF с другим содержимым требует ручной проверки. Полный текст, фрагменты и SQLite-индекс остаются в `data/private/`, исключённой из Git. В репозитории сохраняются метаданные и короткие авторские карточки.

`python scripts/run_therapy_experiment.py` фиксирует протокол без запросов. Вариант с `--live` разрешает максимум 56 заданий на 14 точек и две модели. Существующий журнал не отправляется повторно; зависшие и ошибочные задания требуют отдельного разбора. Изменение входов блокируется проверкой протокола. Не удаляйте журналы для обхода этой защиты.

Повторный опыт запускается отдельно: `python scripts/run_therapy_revision.py --live`. Его максимальный бюджет составляет 64 задания: 8 новых срезов × 2 модели × 2 роли × 2 версии. Метки зафиксированы до обращений к моделям. Порядок версий чередуется. Изменены одновременно временные признаки, напоминание об исключениях и независимость проверки; вклад каждого изменения по отдельности не измерен. Для просмотра результатов используйте `--summarize`, он не вызывает API.

## Исходное сравнение 04.11.2026

Все 56 заданий завершились. У Gemini совпали 51/56 статусов и 7/14 наборов действий; у Gemma 54/56 и 13/14. Для следующей итерации предварительно выбрал Gemma, поэтому она выбрана в локальном интерфейсе. Медиана задания выше: 51,47 с против 20,69 с. Обе модели допускали ошибки времени, поэтому выводы сопоставляются с расчётом программы. Это инженерный эксперимент на авторских сценариях, без клинического эталона.

## Повторное сравнение версий

На восьми новых случаях выполнил 64 задания; 61 ответ прошёл строгую проверку, три ошибки формата сохранены. На общих завершённых случаях у Gemma совпадения статусов изменились с 22/28 до 27/28, наборов действий с 2/6 до 5/6. У Gemini: с 26/32 до 28/32 статусов, наборы действий остались 1/8. Подробности, исключённые из парного сравнения случаи и ограничения находятся в [описании этапа](docs/13-therapy-stage.md) и [HTML-отчёте](reports/week-2-report.html).

Новые интервалы уменьшают часть ошибок, но не обеспечивают безошибочную работу. Строгий опыт и очистка Markdown-метки в приложении учитываются отдельно. Ошибочные ответы не заменены исправленными и не отправлены повторно.
