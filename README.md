# ITMO AIMedicine

Учебный проект медицинского помощника и проверки документации. На первом этапе подготовлены исследование, архитектура, синтетические примеры и окружение Python + Vue. Первая запланированная функция проверяет полноту истории болезни взрослого пациента с внебольничной пневмонией и показывает основания из клинических рекомендаций.

**Рабочий провайдер для разработки: Mistral.** Google AI Studio перенаправлял на страницу доступных регионов, поэтому ключ Gemini получить не удалось. К Gemini/Gemma вернёмся позже, когда появятся время и доступ. Причина похожа на региональное ограничение, но отдельно от других условий аккаунта она не подтверждена.

Сейчас приложение умеет показывать настройки и выполнять технический запрос к модели. По умолчанию включена локальная имитация (`mock`), которая вообще не обращается к API. Реальный запрос Mistral в этом проекте ещё не выполнялся по просьбе владельца. Клиническая проверка истории болезни описана в спецификации, но ещё не реализована.

## Запуск

Нужны Python 3.11+ и Node.js 22.12+; локально проверены Python 3.12.14 и Node.js 26.4.0. Все команды Python выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
pip install --no-deps -e .
python -m itmo_aimedicine.cli --mode mock
uvicorn itmo_aimedicine.api:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
```

Откройте `http://127.0.0.1:5173`. Кнопка проверяет локальную имитацию. Сервер привязан к локальному адресу; вход для внешних пользователей пока не предусмотрен.

## Когда будет ключ Mistral

Скопируйте `.env.example` в `.env` и заполните `MISTRAL_API_KEY` в редакторе. Файл исключён из Git. Ключ не нужен браузеру. Для отдельной проверки выполните:

```bash
python -m itmo_aimedicine.cli --mode live --output reports/live/smoke.json
```

Команда отправляет технический текст без медицинских данных. Она сохраняет модель, режим, число попыток, задержку и расход токенов. Ошибка не подменяется локальным ответом. Для реального запроса из интерфейса нужно отдельно задать `LLM_MODE=live` в `.env`.

По умолчанию выбрана `ministral-8b-latest`, как в отборочном проекте. Доступность этой модели и квота текущего ключа пока не проверены. Модель меняется через `MISTRAL_MODEL`.

## Проверки и сборка отчёта

```bash
python scripts/generate_cases.py
python -m pytest -q --junitxml=reports/checks/pytest.xml
python -m itmo_aimedicine.cli --mode mock --output reports/checks/mock-smoke.json
python scripts/build_report.py
```

Для интерфейса: `cd frontend && npm run build`. В CI запускаются только проверки без ключей. Подробные результаты находятся в [журнале проверки](docs/08-validation.md).

В качестве основы подключения изучен [отборочный AIMedicine](https://github.com/VAVASTO/AIMedicine/tree/e2f4877), коммит `e2f4877`. Из него взяты подход к HTTP-запросам, JSON Schema, ограничениям повторов и обработке ошибок. Исторические ответы модели и интерфейс Streamlit в новый проект не перенесены.
