# ITMO AIMedicine

Учебный проект ИИ-помощника для клинической работы и экспертизы медицинской документации. На первом этапе я исследовал процессы врача и эксперта ОМС, сравнил 12 подходов и продуктов, составил реестр из 24 типов документов и спроектировал обе ветви системы. Доработка исследования: 25 октября 2026 года.

**Подключены Mistral напрямую и GLM через FreeTheAI; по умолчанию выбран Mistral.** Google AI Studio перенаправлял на страницу доступных регионов. 18 октября 2026 года я повторил попытку с телефона через VPN США, но ключ создать также не удалось: кнопка была недоступна либо интерфейс указывал на отсутствие прав. Причина ограничения пока не установлена. К Gemini/Gemma вернусь после решения проблемы доступа; подробности попыток приведены в [отчёте о подключении моделей](docs/07-models.md).

Сейчас приложение умеет показывать настройки и выполнять технический запрос к модели. По умолчанию включена локальная имитация (`mock`), которая вообще не обращается к API. 18 октября 2026 года я проверил реальное подключение на `ministral-8b-2512`: один успешный запрос, 73 токена. 25 октября проверил GLM на 14 учебных сценариях, затем сравнил GLM и Mistral на 12 новых коротких историях: 36 запросов, без повторов. Полная клиническая функция пока описана в спецификации; эксперимент проверяет только ответы по заданному критерию.

## Запуск

Нужны Python 3.11+ и Node.js 22.12+; локально я проверял проект с Python 3.12.14 и Node.js 26.4.0. Все команды Python выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
pip install --no-deps -e .
python -m itmo_aimedicine.cli --mode mock
uvicorn itmo_aimedicine.api:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
```

Откройте `http://127.0.0.1:5173`. Кнопка проверяет локальную имитацию. Сервер привязан к локальному адресу; вход для внешних пользователей пока не предусмотрен.

## Подключение Mistral

Скопируйте `.env.example` в `.env` и заполните `MISTRAL_API_KEY` в редакторе. Файл исключён из Git. Ключ не нужен браузеру. Для отдельной проверки выполните:

```bash
python -m itmo_aimedicine.cli --mode live --output reports/live/smoke.json
```

Команда отправляет технический текст без медицинских данных. Она сохраняет модель, режим, число попыток, задержку и расход токенов. Ошибка не подменяется локальным ответом. Для реального запроса из интерфейса нужно отдельно задать `LLM_MODE=live` в `.env`.

По умолчанию выбрана проверенная модель `ministral-8b-2512`. Модель меняется через `MISTRAL_MODEL`.

Для локальной проверки я сохранил ключ в `.env`, включил `LLM_MODE=live`, ограничил ответ 128 токенами и задал одну попытку запроса. Ключ бессрочный, привязан к `Default Workspace`, доступ к подключениям ограничен `Shared only`. Приложение вызывает только модель, инструменты подключений не использует.

На момент проверки в аккаунте активен Free с включённым объёмом API/Studio на $10 в месяц; API pay-as-you-go выключен. Для работы в пределах бесплатного тарифа оставьте его выключенным. Приложение не меняет подписку и не проверяет её состояние при каждом запросе. Результат проверки я сохранил в `reports/checks/mistral-live.json`; ключ в него не входит.

## Проверка GLM через FreeTheAI

Добавил отдельный адаптер для `fta/zai/glm-5.3` и `fta/zai/glm-5.3-flash`. Он обращается только к `https://api.freetheai.org/v1`, делает одну попытку и не переключается на другую модель при ошибке. Ответ проверяется локально по схеме; неподходящий ответ отклоняется. Настройку Mistral можно использовать отдельно.

Файл с ключом можно передать при запуске, без копирования в репозиторий:

```bash
python -m itmo_aimedicine.cli --provider glm --env-file /path/to/free-models.env --mode live --output reports/live/glm-smoke.json
```

Для приложения GLM выбирается через `LLM_PROVIDER=glm` и переменные `FREETHEAI_*` из `.env.example`. При `LLM_MODE=mock` запросов к API нет.

Подготовил отдельный эксперимент на 14 вымышленных вариантах одной семьи. Команда без `--live` только сохраняет входы; добавление `--live` отправляет максимум 14 запросов. При ошибке запуск останавливается. Каталог результатов должен быть новым, чтобы случайно не перезаписать и не повторить прежний эксперимент.

```bash
python -m itmo_aimedicine.glm_trial --env-file /path/to/free-models.env --output-dir reports/live/glm-trial-new --limit 14
```

25 октября 2026 года все 14 целевых статусов GLM совпали с ожиданиями; в одном объяснении модель упомянула сведения из будущего документа. С технической проверкой использовал 15 запросов, без повторов. [Ответы и ограничения эксперимента](docs/11-glm-trial.md) включены в отчёт первой недели. Это проверка модели на заданной спецификации, а не готовая клиническая функция или независимая оценка её точности. Ожидаемые статусы не входят в запросы. Ключи и исходные локальные журналы исключены из Git; очищенные результаты сохранены в `reports/checks/glm-trial-2026-10-25.json`.

## Сравнение на 12 новых историях

GLM дала 12/12 ожидаемых статусов и со всей картой, и после отбора доступных документов. Mistral на тех же отфильтрованных входах дала 10/12; все автоматические проверки прошли 9/12 ответов. Медиана задержки GLM после фильтра 9,67 с, Mistral 2,56 с. Для следующего инженерного опыта предварительно выбрал GLM с фильтром; настройка приложения по умолчанию остаётся Mistral. Улучшение качества от фильтра на этом наборе не показано.

Новый эксперимент использовал 24 запроса GLM и 12 Mistral. Аккаунт FreeTheAI после него показал 40/50, осталось 10 на этот суточный период. Повторов и платных настроек нет. Авторские случаи, промпт, схема и ожидания зафиксированы в `data/research/comparison-v1/`; клинической разметки нет. Полные ответы и разбор сохранены в `reports/checks/comparison-2026-10-25.json` и `reports/checks/comparison-manual-review.json`.

Поиск проверен отдельно без API: 9 авторских карточек, 12 запросов. Точное извлечение по вручную заданным ключам даёт 12/12 первых попаданий, BM25 с фильтром 11/12, без фильтра 9/12. Это не проверка автоматического выбора критерия или полного корпуса.

`python scripts/summarize_comparison.py` пересобирает результаты из локальных журналов без запросов. Для HTML достаточно сохранённых файлов из `reports/checks/`. Сравнительный запуск блокирует повтор существующего эксперимента и считает каждую попытку до запроса; новый запуск требует отдельного плана и бюджета.

## Проверки и сборка отчёта

```bash
python scripts/generate_cases.py
python -m itmo_aimedicine.cli --mode mock
python scripts/build_research_data.py
python scripts/build_feature_packet.py
python -m pytest -q --junitxml=reports/live/pytest-current.xml
python scripts/build_report.py
```

Для интерфейса: `cd frontend && npm run build`. После добавления GLM прошли 59 тестов и сборка интерфейса; после сравнительного эксперимента прошли 69 локальных тестов. Интерфейс с тех пор не менялся. В CI запускаются только проверки без ключей. Свежий запуск сохраняется в `reports/live/pytest-current.xml`, чтобы не перезаписывать исторические журналы. Сборка отчёта использует сохранённые результаты и не вызывает модели. Подробности находятся в [журнале проверки](docs/08-validation.md).
