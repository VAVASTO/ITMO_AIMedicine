   Status is a coloured badge: worked (teal), partial (amber), failed (red).

   Each section starts with a one-sentence takeaway ("Вывод:"), then evidence (figures, tables, diagrams, code), then limitations.
4. "Что не получилось и почему": a consolidated list of failed attempts with evidence-based reasons.
5. "Следующие шаги": concrete, checkable items for next week (max 7).
6. Footer: how to reproduce (only if the information was provided), generation date.
</required_structure>

<design_system>
Calm "scientific journal meets product dashboard" look, consistent with the reference style of the platform.
- CSS variables: black #050504, ink #16140F, text #2B2924, muted #6E6A60, line #E4E0D6, soft #F6F4EF, paper #FFFFFF,
  page background #EDEAE3; amber #E2A12B (deep #B67A0E, wash #FCF3E1) as the main accent; teal #1F8A7A (wash #E6F4F1);
  slate #3D4B63 (wash #EBEEF4); danger #B3261E (wash #FBEAE8).
- Fonts via Google Fonts <link> with system fallbacks: "Bricolage Grotesque" for headings, "Instrument Sans" for text,
  "JetBrains Mono" for code and numbers.
- Layout: max-width 1180px, generous whitespace, a dark hero block at the top, white cards with 1px borders and
  12-14px radius, small amber "section tags" above headings, chips with wash backgrounds, stat tiles with a 3px amber top border,
  chevron-style flow diagrams, sticky section navigation with scroll-spy.
- Dark code blocks (#050504) with horizontal scroll and a copy button.
- Amber is the only accent colour; teal / red are used ONLY for result status. No gradients, neon, emojis or stock photos.
- Mobile-first: fully usable at 360 px; tables scroll horizontally inside their card; SVG uses viewBox and scales.
- Print: @media print hides navigation, expands collapsed blocks, avoids page breaks inside figures and tables.
</design_system>

<interactivity>
Genuinely useful, never gimmicky:
- collapsible sections (<details>) with "expand all / collapse all";
- table filter and sort;
- charts with hover tooltips, exact values, and a clickable legend that toggles series;
- architecture diagrams as inline SVG with hover highlight and a short explanation panel;
- code snippets with lightweight syntax highlighting (hand-written tokenizer, no libraries) and a copy button;
- when it helps the story, an "iceberg" block: visible results on top, hidden work below the waterline
  (failed attempts, dead ends, debugging, data cleaning, compute spent).
</interactivity>

<technical_constraints>
- ONE .html file: inline <style> and <script>, vanilla JavaScript (ES2020), no build step, no frameworks.
- Charts: draw by hand with inline SVG or <canvas>. If a library is unavoidable, load ONE pinned version from https://cdnjs.cloudflare.com only.
- The page runs inside a sandboxed iframe: do NOT use localStorage, sessionStorage, cookies, indexedDB, window.top, form submissions.
  Wrap anything risky in try/catch.
- No external images, no trackers, no network requests except the listed assets, Google Fonts and the single optional cdnjs library.
- Accessibility: semantic HTML (header / main / section / figure / table with <caption>), alt texts, contrast >= 4.5:1,
  keyboard-focusable controls, respect prefers-reduced-motion.
- Keep JavaScript under ~1500 lines; render heavy charts lazily when their section is opened.
</technical_constraints>

<scientific_quality_rules>
- NEVER invent data. Use only the numbers and facts given in this prompt and in the assets.
  If something is missing, show a visible badge "нужно уточнить" instead of making it up.
- Every chart: title, axis labels with units, legend, source (asset name) and the number of runs / samples if known.
- Label statements explicitly as "Факт", "Интерпретация" or "Гипотеза".
- Report negative and null results with the same care as positive ones: what was tried, why it failed (evidence), what it implies.
- State limitations and threats to validity (small data, single run, no seeds, differing conditions).
- Compare approaches with the same metric and conditions; if conditions differ, say so.
- Mention related work only if it was provided; never fabricate references.
</scientific_quality_rules>
